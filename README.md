# dsh-initalGithubRepository

适用于 DeepSeek Harness 的 Git 自动提交插件：每轮对话结束后自动生成规范化的提交信息并推送代码，分支与提交树优先读取本地 Git 数据，仅在检测到远程差异时更新；支持从任意分支新建分支、工作区合并与 Rebase、会话内提交树版本回退，以及按会话与工作区配置仓库、分支、README AI 更新、提交前确认和手动重试。

## 功能

- **自动提交**：每轮对话结束后生成规范化的 Commit 信息并推送代码；提交前会弹出确认，确认后隐藏窗口并在后台执行。
- **分支选择**：会话与工作区的分支改为下拉选择，打开设置时优先读取本地 Git 数据（本地分支与本地记录的远程分支），再用 `git ls-remote` 检测线上状态：一致时直接使用本地数据、不执行 fetch，检测到差异才更新远程跟踪引用并刷新；面板会提示“本地分支引用与远程一致”或“检测到远程分支变化，已更新本地引用”。优先显示当前分支和默认分支；修改仓库地址后可点“刷新分支”重新读取。
- **新建分支**：在分支下拉中选择“＋ 新建分支…”，指定基于哪个分支以及新分支名；首次提交时从所选 base 创建并切换分支，如果远程已有同名分支则会拒绝创建，以避免覆盖。
- **工作区分支操作**：可把指定来源分支合并到工作区当前检出的分支，或把当前分支 rebase 到目标分支；发生冲突时会自动中止并报告冲突文件，操作前要求工作区干净，可选完成后推送（使用普通 push，不会自动 force push）。
- **版本回退**：在会话设置中打开提交树（最多展示最近 1,000 个提交），提交树同样先用本地 refs 生成，仅在检测到远程差异时 fetch 并重建，并提示本次使用的是本地数据还是已更新远程引用；选择任意提交即可把项目内容恢复到该版本；回退通过一个新提交实现，不会 reset 或删除历史。
- **版本同步与手动重试**：会话 Git 设置中新增“版本同步”，以只读、短超时的云端检查对比本地 `HEAD` 与云端目标分支，并显示工作区是否有未提交文件、领先/落后提交数，以及上一次自动提交是否失败及错误信息。当本地与云端不一致、工作区有改动、仓库未初始化、云端检测失败或上次自动提交失败时，会显示“手动提交版本”按钮：有未提交改动时走与自动提交相同的流程（生成 AI commit 信息、按会话开关更新 README、弹出确认窗口后提交并推送）；工作区干净但存在未推送提交时直接重试推送，不会创建空提交；远程历史分叉时会自动合并后重试，冲突则保留本地提交并报错。已有待确认提交时按钮隐藏，设置表单有未保存修改时按钮禁用并提示先保存；云端不可达时保留本地状态并显示警告，手动重试仍然可用。
- **离线回退**：线上检测失败（网络或 Token 问题）时继续使用本地分支与提交数据，并显示警告，不影响当前配置保存。
- **配置与凭据**：按会话与工作区分别配置仓库、分支、是否启用，以及是否由 AI 同步更新 README；GitHub 凭据安全存储。

更多实现细节见 [docs/DETAIL.md](docs/DETAIL.md)。
